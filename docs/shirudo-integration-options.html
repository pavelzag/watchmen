1. The 30-Second Idea

Watchmen Today (v0.9)

Finds problems & watches traffic

Watchmen scans AWS/GCP configs, container images (Trivy), SOC 2 / ISO 27001 controls, and Kubernetes/VM traffic using a read-only eBPF sensor. It also sends remediation tasks to coding agents (OpenCode, Claude Code, Codex) to open Terraform PRs.

Shirudo (OpenAI + Cisco)

Drops a live "shield" on Linux without a restart

When a scary zero-day drops (like Log4Shell / Java4Shell), patching and rebooting servers can take days. Shirudo lets an AI agent write a tiny signed eBPF or Java-bytecode "shield" (upatch) that blocks only the exploit path on the running Linux machine—verified by a hardware TPM chip.

2. How Your Existing Codebase Lines Up

You don't need to reinvent Watchmen. Three Watchmen subsystems already map directly to Shirudo:

Already Built

CLI Task Handoff + MCP

lib/handoff/ + scripts/watchmen-cli.mjs already push security tasks to Codex, Claude Code, and OpenCode. Today they fix Terraform; they can just as easily generate Shirudo shields.

Already Built

Trivy + Runtime API v1

lib/trivy/scanner.ts finds container CVEs and /api/watchmen/v1/runtime/* tracks live attack probes. Shirudo tells you which of those CVEs now have an active shield.

Sensor Only Today

Watchmen eBPF Agent

services/ebpf-agent/ observes HTTP, TCP, and execve on standard VMs/GKE. It is a passive camera—Shirudo is an active, tamper-proof lock.

3. The Big Catch (Read Before Building!)

Shirudo is currently pre-release and picky about the Linux machine it runs on.

Catch #1

Needs a Custom Kernel

Shirudo requires a patched bpf-next Linux kernel + systemd 256+ initrd boot. Standard GKE, Cloud Run, and normal Ubuntu/Debian cloud VMs cannot run it out of the box.

Catch #2

Needs TPM 2.0 Hardware

Production targets require a real TPM 2.0 chip (or cloud vTPM) to prove shields weren't tampered with. Local dev VMs can fake it with a software TPM.

Catch #3

Keys Stay With the Customer

Shirudo's security promise breaks if Watchmen's cloud server holds the private ML-DSA-87 signing key. Keep signing on the customer's laptop or CI/CD runner.

4. Your 5 Integration Options

Recommended First Low Infra Risk

Option 1: "Auto-Shield" via Watchmen CLI Handoff

Effort: 2–3 weeks · Hosting cost: ~$0

Use Watchmen's existing Send to CLI + MCP flow so when Watchmen spots an unpatched CVE or live attack probe, it dispatches a task to Codex / Claude Code / OpenCode on the operator's side to write, test, and sign a Shirudo shield.

  • Pros: Zero private-key risk on Watchmen; almost zero Watchmen server cost; instant demo story ("Watchmen + Codex live-patches a server").
  • Cons: Targets still need Shirudo's Linux image to actually apply the shield.
Recommended Second Telemetry Only

Option 2: Ingest Shirudo Telemetry & TPM Alerts

Effort: 2–4 weeks · Hosting cost: Low

Shirudo targets automatically push two OTLP/HTTP JSON streams every minute: a heartbeat (shirudo.keepalive) with tamper status + active shields, and eBPF map logs (shirudo.bpf.map.snapshot) showing blocked attacks. Watchmen ingests them just like it ingests ebpf-agent events.

  • Pros: Works cleanly with Watchmen's existing Postgres + Runtime UI; doesn't force Watchmen to replace its current eBPF agent.
  • Cons: Needs a small TLS 1.3 PQC / OTel proxy (or tls.classical_hosts config) and an attestation verifier worker if you want cryptographic TPM verification.
High Business Value

Option 3: "Shielded" CVE & Compliance Badges

Effort: 2–3 weeks · Hosting cost: Low

Combine Watchmen's Trivy CVE scans + SOC 2 / ISO 27001 checks with Shirudo's shield status. Instead of showing a scary red "Unpatched Critical CVE", Watchmen shows: "Unpatched in image — Shielded at runtime by signed upatch (TPM verified)".

  • Pros: Huge value for founders doing SOC 2 / ISO 27001 audits—proves compensating controls when a vendor patch isn't out yet.
  • Cons: Depends on Option 2 telemetry (or reading Shirudo's ClickHouse tables).
Architectural Fork

  • Takeaway: Never delete services/ebpf-agent in favor of Shirudo right now—you would lock out every customer on standard GKE, EKS, or Ubuntu VMs.
Heavy Lift

Option 5: Full Shirudo Web Console + Managed Backend

Effort: 2–4 months · Hosting cost: High

Shirudo only ships a terminal viewer (xtop) and ClickHouse SQL tables. Watchmen could become the official web SaaS console on top of Shirudo—managing fleet labels, OCI upatch trees, ClickHouse ingestion, and remote TPM challenge-response attestation.

  • Pros: Could position Watchmen as the "Wiz/UI for Shirudo" if Shirudo takes off across enterprises.
  • Cons: High ops burden (ClickHouse, OTel, custom VM images) and pulls Watchmen away from its simple startup-friendly single-Postgres stack.

6. Product Impact: Marketing, Costs, Friction & Pricing

Per pitch.md, Watchmen wins by giving startups enterprise security without six-figure Wiz/Prisma budgets or complex setup. Here is how Shirudo affects the business:

Marketing & Positioning
Huge Early-Mover Halo
  • Ride the OpenAI + Cisco wave: Shirudo just launched (Nov 23, 2026). Being the first open/startup CSPM with a working "Detect in Watchmen → Shield with Shirudo" demo is prime material for HN, LinkedIn, Product Hunt, and OpenAI/Isovalent community showcases.
  • New category story: Shifts Watchmen from "we tell you what's broken" (like every CSPM) to "we help your AI coding agent shield it live before you even reboot."
  • Enterprise credibility: TPM hardware attestation + post-quantum TLS 1.3 gives Watchmen serious security-team street cred when startups grow into mid-market buyers.
Customer Friction & Churn Risk
Must Stay Optional
  • The Startup Paradox: Early-stage teams use Vercel, Cloud Run, standard GKE, or plain Ubuntu EC2—none of which support Shirudo's custom kernel + TPM today.
  • Don't break onboarding: Watchmen's superpower is 5-minute Docker/mock onboarding with zero dedicated security hire. Making Shirudo mandatory would crush activation.
  • Best framing: Offer Shirudo as an opt-in "Shielded Mode / Lab" or a 1-click local VM demo, while keeping standard Watchmen agentless + ebpf-agent as the default.
Your Engineering & Hosting Costs
Low if Scoped Smartly
  • Options 1–3 (Watchmen server): Almost free. AI shield generation uses the customer's own OpenAI/Claude/OpenCode CLI keys; small telemetry fits right in your existing Neon/Postgres DB.
  • If you build shields in Watchmen Cloud (avoid): Requires heavy Linux build workers (clang 23, veritysetup, OCI storage) and creates key-custody liability.
  • If you host ClickHouse (Option 5): Adds real cloud bills (~$150–$600+/mo baseline cluster) and ops complexity; only do this if paying enterprise customers demand 1,000+ node fleets.
Monetization & Tiering
Natural Pro / Enterprise Upsell
  • Free / Startup Tier: AWS/GCP posture + SOC 2 / ISO 27001 + Trivy scans + standard ebpf-agent sensor + Terraform PR handoff.
  • Pro Tier ($): AI Auto-Shield templates in CLI Handoff + "Shielded at Runtime" CVE badges for auditors.
  • Enterprise / Regulated Tier ($$$): Hardened Linux VM blueprints (Terraform/Packer), OTLP ingest, and TPM-verified fleet attestation reports.

7. Recommended 3-Step Rollout

Bottom Line: Integrate Shirudo as an AI-assisted shield workflow (Option 1) + telemetry/compliance layer (Options 2 & 3) first. You get 90% of the marketing upside and enterprise differentiation for near-zero server cost, without breaking Watchmen's frictionless startup experience.
