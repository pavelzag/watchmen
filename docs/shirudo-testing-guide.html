5. Track D: Testing Cryptographic TPM 2.0 Quotes, Replay Detection & Attestation

Watchmen implements a native Node.js binary parser in lib/shirudo/tpm-verify.ts that checks: (1) TPMT_PUBLIC (ECC NIST P-256 + SHA-256), (2) TPMS_ATTEST magic (0xff544347) & type (0x8018), (3) extraData === SHA256(keepaliveBody) (or exact 32-byte nonce for challenges), (4) ECDSA-SHA256 signature, and (5) monotonic (resetCount, clock) counters to detect VM snapshot rollbacks or replayed keepalives (historyContradiction).

Synthetic TPM 2.0 Quote Generator Script (No Hardware TPM Required)

Save or run this one-liner script against your local Watchmen server to test (a) valid TPM quote verification, (b) monotonic rollback detection, and (c) on-demand challenge attestation:

node --input-type=module -e '
import { createHash, generateKeyPairSync, sign as cryptoSign } from "crypto";

const WATCHMEN_URL = process.env.WATCHMEN_URL || "http://localhost:3000";
const WM_TOKEN = process.env.WM_TOKEN;
if (!WM_TOKEN) throw new Error("Set WM_TOKEN=wm_... first");

const u8 = (n) => Buffer.from([n]);
const u16 = (n) => { const b = Buffer.alloc(2); b.writeUInt16BE(n); return b; };
const u32 = (n) => { const b = Buffer.alloc(4); b.writeUInt32BE(n); return b; };
const u64 = (n) => { const b = Buffer.alloc(8); b.writeBigUInt64BE(n); return b; };

function buildTpmtPublic(x, y) {
  return Buffer.concat([
    u16(0x0023), u16(0x000b), u32(0x00030072), u16(0),
    u16(0x0010), u16(0x0010), u16(0x0003), u16(0x0010),
    u16(x.length), x, u16(y.length), y,
  ]);
}
function buildTpmsAttest(extraData, resetCount, clock, pcrMask = 0) {
  const qs = Buffer.from("signer");
  return Buffer.concat([
    u32(0xff544347), u16(0x8018), u16(qs.length), qs,
    u16(extraData.length), extraData,
    u64(BigInt(clock)), u32(resetCount), u32(0), u8(1), u64(1n),
    u32(1), u16(0x000b), u8(3), Buffer.from([pcrMask, 0, 0]),
    u16(32), Buffer.alloc(32, 0xaa),
  ]);
}
function makeQuote(privateKey, akBytes, extraData, resetCount, clock, pcrMask = 0) {
  const attest = buildTpmsAttest(extraData, resetCount, clock, pcrMask);
  const sig = cryptoSign("sha256", attest, { key: privateKey, dsaEncoding: "ieee-p1363" });
  const tpmtSig = Buffer.concat([u16(0x0018), u16(0x000b), u16(32), sig.subarray(0, 32), u16(32), sig.subarray(32, 64)]);
  return `attest=${attest.toString("base64")};sig=${tpmtSig.toString("base64")};ak=${akBytes.toString("base64")}`;
}

const { publicKey, privateKey } = generateKeyPairSync("ec", { namedCurve: "prime256v1" });
const jwk = publicKey.export({ format: "jwk" });
const akBytes = buildTpmtPublic(Buffer.from(jwk.x, "base64url"), Buffer.from(jwk.y, "base64url"));
const akName = "000b" + createHash("sha256").update(akBytes).digest("hex");

async function postJson(path, body) {
  const res = await fetch(`${WATCHMEN_URL}${path}`, {
    method: "POST",
    headers: { Authorization: `Bearer ${WM_TOKEN}`, "Content-Type": "application/json" },
    body: JSON.stringify(body),
  });
  return res.json();
}

// 1) Valid keepalive with TPM quote (resetCount=5, clock=10000)
const bodyStr1 = JSON.stringify({ schema: "shirudo.keepalive/1", kernel_release: "7.4.0-bpf-next+shirudo", verdict: "ok", cond: 5461, flags: 0, count: 1 });
const q1 = makeQuote(privateKey, akBytes, createHash("sha256").update(bodyStr1).digest(), 5, 10000);
console.log("1. Valid quote ingest:", await postJson("/api/ingest/shirudo/v1/logs", {
  resourceLogs: [{ resource: { attributes: [{ key: "host.name", value: { stringValue: "tpm-sim-node" } }] },
    scopeLogs: [{ logRecords: [{ eventName: "shirudo.keepalive", body: { stringValue: bodyStr1 }, attributes: [{ key: "shirudo.quote", value: { stringValue: q1 } }] }] }] }]
}));

// 2) Issue & verify an on-demand nonce challenge
const issued = await postJson("/api/shirudo/attest", { action: "issue", nodeKey: akName });
console.log("2a. Issued challenge:", issued.command);
const qChal = makeQuote(privateKey, akBytes, Buffer.from(issued.challenge.nonce, "hex"), 5, 11000, 0x02);
console.log("2b. Verified challenge:", await postJson("/api/shirudo/attest", { action: "verify", challengeId: issued.challenge.id, quote: qChal }));

// 3) Replay / Rollback contradiction test (clock=9000 < previous 10000)
const bodyStrRollback = JSON.stringify({ schema: "shirudo.keepalive/1", kernel_release: "7.4.0-bpf-next+shirudo", verdict: "ok", cond: 5461, flags: 0, count: 1 });
const qRollback = makeQuote(privateKey, akBytes, createHash("sha256").update(bodyStrRollback).digest(), 5, 9000);
console.log("3. Rollback keepalive:", await postJson("/api/ingest/shirudo/v1/logs", {
  resourceLogs: [{ resource: { attributes: [{ key: "host.name", value: { stringValue: "tpm-sim-node" } }] },
    scopeLogs: [{ logRecords: [{ eventName: "shirudo.keepalive", body: { stringValue: bodyStrRollback }, attributes: [{ key: "shirudo.quote", value: { stringValue: qRollback } }] }] }] }]
}));
'

After running step 1 & 2, tpm-sim-node appears on /dashboard/runtime with a TPM Verified badge and akName node key (000b...). After step 3, the node flips to Replay / Rollback (historyContradiction: true), and stays flagged on subsequent updates.

6. Track E: Live Demo on Static-Studio Dev (theinsite-dev + theinsite-watchmen)

To run a real live-patching demo on Static-Studio's GCP dev environment—where you reproduce an actual kernel vulnerability, patch it live with zero reboot, and see Watchmen reflect the shield—use a dedicated nested-KVM GCE VM in theinsite-dev reporting to Watchmen hosted in theinsite-watchmen (https://watchmen.theinsite.dev).

Do not modify cms-dev-vm or cms-dev-lior-vm: Shirudo requires a custom-patched bpf-next kernel (tpm_command & mm_read_access LSM hooks, CONFIG_CRYPTO_MLDSA, signed-loader ABI), systemd 256+ initrd boot, and TPM 2.0. Condition Bitmask (cond) — 7 Bit-Pairs (LSB First)

Each condition uses 2 bits: 00 = unset, 01 = ok, 10 = warn, 11 = alert. Value 5461 (0b01_01_01_01_01_01_01) means all 7 conditions are ok.

Common Gotchas During Testing

  • Why does SHIELDED not appear on my CVE yet? A CVE shows SHIELDED only when (1) a mapping exists in shirudo_upatch_fixes for that exact uppercase CVE ID, AND (2) at least one node with verdict: "ok" or "degraded" reports that upatchId in loaded_upatches (populated via shirudo.bpf.map.snapshot) OR has loaded_upatches = [] with keepalive count > 0.
  • Why did my keepalive quote fail with extraData mismatch? Keepalive quote verification hashes the exact UTF-8 bytes of body.stringValue (SHA-256). Re-serializing or pretty-printing the JSON string after signing invalidates the quote.
  • Why did my keepalive quote fail with PCR bits error? Keepalive quotes expect empty PCR selection (requireEmptyPcrSelect: true); only on-demand challenge quotes allow non-empty PCR selection bits.
  • Why is historyContradiction stuck true? Once a node reports a lower (tpmResetCount, tpmClock) than previously recorded, shirudo_nodes.history_contradiction latches to TRUE (OR EXCLUDED.history_contradiction) until the row is cleared or reset by an operator.
