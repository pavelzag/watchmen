# Watchmen v0.9: CLI Task Handoff Plan (OpenCode, Claude Code, Codex)

## Goal

Watchmen v0.9 introduces **CLI Task Handoff**: the ability to push security findings, attack paths, and remediation context discovered by Watchmen into open tasks for local AI coding CLIs such as **OpenCode**, **Claude Code**, and **Codex**, without requiring Watchmen to run on the developer's workstation.

## Architecture Overview

Watchmen separates **Task Normalization + Queueing** (server-side in Watchmen) from **Delivery Adapters** (UI commands/exports, MCP tools, and local CLI runners):

```text
Watchmen Findings / Attack Paths / Agent Investigations & Plans
        |
        v  (normalize + redact secrets + batch + fingerprint)
Watchmen Handoff Queue (Postgres: cli_handoff_tasks)
        |
        v  (REST API /api/handoff/tasks + Bearer wm_... API tokens)
  +-----+------------------------------+-------------------------------+
  |                                    |                               |
  v                                    v                               v
Phase 1 (v0.9):                   Phase 2:                        Phase 3:
UI "Send to CLI" Modal            Watchmen MCP Server             Local Runner (`watchmen-cli`)
- Push & deduplicate tasks        - watchmen_list_open_tasks      - Polls / streams open tasks
- Copyable commands per CLI       - watchmen_get_task             - Spawns opencode/claude/codex
- Download TASKS.md / JSON pack   - watchmen_claim/complete_task  - Git worktree isolation + PR sync
```

## Phase 1 (Implemented in v0.9)

### 1. Canonical Task Schema & Batching (`lib/handoff/tasks.ts`)
- Normalizes Watchmen issues (`SecurityFinding`, `AwsSecurityFinding`, `AttackPath`, and optional `investigationReport` / `proposedPlan`) into `HandoffIssueItem[]`.
- Reuses `buildRemediationBatchSuggestions()` from `lib/github/remediation-targets.ts` to support three grouping modes:
  - **Grouped by category** (`grouped`, default): splits findings into focused batches (`iam`, `firewall`, `cloud_run`, `cloud_sql`, `storage`, `service_accounts`, `other`).
  - **Single combined task** (`combined`): packages all selected issues into one task.
  - **One task per issue** (`individual`): creates one task per issue.
- Generates deterministic SHA-256 `fingerprint` values (`user + batchMode + sorted issue IDs`) so re-pushing already-open issues updates the existing open task instead of creating duplicates.
- **Secret Redaction**: scrubs sensitive values (connection string passwords, Bearer tokens, private key headers, GCP/OpenAI/Anthropic/AWS/GitHub token patterns) before persisting prompts or exporting CLI commands/files.
- Generates ready-to-run **per-CLI commands** for:
  - **OpenCode**: `opencode run "..."`
  - **Claude Code**: `claude "..."` (and `claude -p "..."`)
  - **Codex**: `codex "..."` (and `codex exec "..."`)
  - **Generic / API**: `curl -H "Authorization: Bearer $WATCHMEN_API_TOKEN" .../api/handoff/tasks/:id`
- Builds downloadable **Agent Task Packs** (`TASKS.md` and `watchmen-tasks.json`).

### 2. Database Schema (`lib/db.ts` & `scripts/migrate.sql`)
- `user_api_tokens`:
  - Stores scoped Watchmen Personal API Tokens (`wm_...`) as SHA-256 hashes (`token_hash`), storing only `token_prefix` for display, plus `last_used_at` and `revoked_at`.
- `cli_handoff_tasks`:
  - Stores normalized task metadata (`id`, `user_email`, `fingerprint`, `title`, `target_tool`, `batch_mode`, `status`, `severity`, `issue_count`), `payload` (JSONB), `prompt_markdown`, and lifecycle fields (`pr_url`, `session_ref`, `claimed_by`, `claimed_at`, `completed_at`).
  - Supported statuses: `open`, `claimed`, `in_progress`, `completed`, `dismissed`.

### 3. Authenticated REST API
- **Personal API Tokens** (`/api/settings/api-tokens`, session-authenticated):
  - `GET`: list active/revoked token metadata (never returns raw token).
  - `POST`: generate a new `wm_...` token and return the plaintext once.
  - `DELETE`: revoke a token by `id`.
- **Handoff Tasks** (`/api/handoff/tasks` & `/api/handoff/tasks/[id]`, authenticated via either browser NextAuth session **or** `Authorization: Bearer wm_...`):
  - `GET /api/handoff/tasks`: list tasks filtered by `status`, `severity`, `tool`, `limit`.
  - `POST /api/handoff/tasks`: create or idempotently update open tasks from submitted issues, returning `{ tasks, createdCount, updatedCount }`.
  - `GET /api/handoff/tasks/[id]`: fetch a single task (JSON + `promptMarkdown`).
  - `PATCH /api/handoff/tasks/[id]`: update `status`, `targetTool`, `prUrl`, `sessionRef`, `claimedBy`.
  - `DELETE /api/handoff/tasks/[id]`: delete/remove a task.

### 4. Dashboard UI
- **`components/PushToCliModal.tsx`**:
  - Allows choosing target CLI (`opencode`, `claude`, `codex`, `any`) and grouping mode (`grouped`, `combined`, `individual`).
  - Pushes tasks to `/api/handoff/tasks`, displays created/updated task cards with copyable CLI commands and API fetch snippets, and lets users download `TASKS.md` or `watchmen-tasks.json`.
- **Findings (`/dashboard/findings`)**:
  - Header button **Send to CLI** pushes all currently filtered findings.
  - Per-finding **CLI** button pushes a single finding along with any generated investigation report or remediation plan.
- **Attack Paths (`/dashboard/attack-paths`)**:
  - Header button **Send to CLI** pushes all currently visible GCP and AWS attack paths.
- **Settings (`/dashboard/settings` → Integrations)**:
  - Added **CLI & MCP Personal API Tokens** management card (create, copy once, inspect last-used timestamp, revoke).

### Phase 2 (Implemented in v0.9): Watchmen MCP Server
- **Streamable HTTP MCP Endpoint (`/api/mcp` + `lib/handoff/mcp.ts`)**:
  - Authenticated via `Authorization: Bearer wm_...` (or active browser session).
  - Exposes 4 MCP tools over JSON-RPC 2.0 (`protocolVersion: "2025-03-26"`):
    - `watchmen_list_open_tasks`: list tasks filtered by `status`, `severity`, `tool`, `limit`.
    - `watchmen_get_task`: fetch full structured payload and `promptMarkdown` for a task ID.
    - `watchmen_claim_task`: mark a task `claimed` or `in_progress` with `claimedBy` and `sessionRef`.
    - `watchmen_complete_task`: mark a task `completed` or `dismissed` and attach `prUrl` / `sessionRef`.
- **Zero-Dependency Local Stdio Bridge (`scripts/watchmen-mcp.mjs`, `npm run mcp`)**:
  - Calls `/api/handoff/tasks` over HTTP using `WATCHMEN_URL` and `WATCHMEN_API_TOKEN` for CLI configurations that prefer `stdio` transport.
- **Dashboard Integration**:
  - **Settings → Integrations (`components/CliApiTokensCard.tsx`)**: Added copyable MCP setup snippets for **OpenCode**, **Claude Code**, and **Codex** (both remote `/api/mcp` and local `stdio`).
  - **Send to CLI Modal (`components/PushToCliModal.tsx`)**: Added **MCP** command mode alongside **REST API** and **Inline Prompt**.
  - **Tasks Page (`/dashboard/tasks` + `components/CliHandoffQueue.tsx`)**: Live **CLI & MCP Task Queue** viewer showing task statuses, PR links, claimed-by metadata, and complete/dismiss/reopen/delete/verify controls.

### Phase 3 (Implemented in v0.9): Local Watcher CLI (`watchmen-cli`) & Closed-Loop Verification

- **Local Runner & Watcher (`scripts/watchmen-cli.mjs`, `npm run cli`)**:
  - Subcommands: `list`, `pull <taskId>`, `run <taskId>`, `watch`, and `verify <taskId>`.
  - Tool adapters:
    - **OpenCode**: Spawns `opencode run <prompt>` or dispatches directly to a running local OpenCode HTTP server (`--opencode-url` / `OPENCODE_SERVER_URL`).
    - **Claude Code**: Spawns `claude -p <prompt>` (or interactive `claude` with `--interactive`).
    - **Codex**: Spawns `codex exec <prompt>` (or interactive `codex` with `--interactive`).
    - **Custom**: Executes any `--cmd` shell template (`{{promptFile}}`, `{{taskId}}`, `{{title}}`).
  - **Git Worktree Isolation (`--worktree`)**: Creates an isolated `.watchmen-worktrees/<taskId>` worktree on branch `watchmen/<taskId>` per task so concurrent or repeated runs do not disturb the user's working tree.
  - **PR Detection & Status Sync**: Automatically claims tasks as `in_progress`, extracts GitHub PR URLs from agent output, and marks tasks `completed` via `PATCH /api/handoff/tasks/:id`.
- **Closed-Loop Verification (`lib/handoff/verify.ts`, `POST /api/handoff/tasks/[id]/verify`, `watchmen_verify_task` MCP tool)**:
  - Re-checks all task issues against Watchmen's latest stored GCP/AWS snapshots (including `computeFindings`, `computeAwsFindings`, and `computeAttackPaths`).
  - Runs audited AI verification (`verifyFix` in `lib/agent/verify-fix.ts`) when an AI key is configured, falling back to deterministic snapshot verification when no AI key is present.
  - Stores `lastVerification` summary on the task payload and automatically marks the task `completed` when all issues are resolved.
