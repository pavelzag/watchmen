# eBPF Agent VM Debugging Guide

This guide sets up a Linux VM for developing and debugging the Watchmen eBPF agent from VS Code.

The agent cannot attach real eBPF programs on macOS. Use macOS for editing and the Watchmen UI, and use a Linux VM for the kernel/eBPF runtime.

## Target Architecture

```text
Mac
  VS Code
  Watchmen Next.js app on http://localhost:3000
  local Postgres

Linux VM
  Ubuntu ARM64 or AMD64
  Go 1.22+
  clang, bpftool, libbpf headers
  eBPF agent running with sudo

Flow
  curl traffic in VM
    -> Linux syscall
    -> eBPF raw tracepoint
    -> Go ring buffer reader
    -> stdout, or POST to Mac Watchmen /api/agents/events
```

## 1. Create the VM

### Recommended VM Settings

For Apple Silicon Macs, use an ARM64 Linux VM:

```text
OS: Ubuntu Server 24.04 ARM64
CPU: 2-4 cores
RAM: 4-8 GB
Disk: 30+ GB
Network: shared/NAT
SSH: enabled
```

For Intel Macs or cloud VMs, use Ubuntu Server 24.04 AMD64.

Good local VM options:

- UTM: free and simple
- Parallels: easiest networking
- VMware Fusion: also works

### UTM Quick Setup

1. Download Ubuntu Server ARM64 from Ubuntu.
2. Create a new UTM VM:
   - Virtualize, not emulate, on Apple Silicon.
   - Linux.
   - Select the Ubuntu Server ARM64 ISO.
   - Give it 4 GB RAM and 2 CPU cores minimum.
   - Use shared networking.
3. Install Ubuntu normally.
4. During install, enable OpenSSH server if prompted.

After first boot, log into the VM console and confirm:

```bash
uname -m
```

Expected on Apple Silicon:

```text
aarch64
```

Confirm the kernel exposes BTF:

```bash
ls -lh /sys/kernel/btf/vmlinux
```

If that file does not exist, use a newer Ubuntu kernel before continuing.

## 2. Install Linux Dependencies

Run inside the VM:

```bash
sudo apt-get update
sudo apt-get install -y \
  git \
  curl \
  ca-certificates \
  build-essential \
  clang \
  llvm \
  bpftool \
  libbpf-dev \
  linux-tools-common \
  linux-tools-generic \
  openssh-server \
  rsync
```

Enable SSH:

```bash
sudo systemctl enable --now ssh
```

Install Go 1.22 or newer.

For ARM64:

```bash
curl -LO https://go.dev/dl/go1.22.12.linux-arm64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.22.12.linux-arm64.tar.gz
```

For AMD64:

```bash
curl -LO https://go.dev/dl/go1.22.12.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.22.12.linux-amd64.tar.gz
```

Add Go to your shell:

```bash
echo 'export PATH=/usr/local/go/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
```

Verify:

```bash
go version
clang --version
bpftool version
```

## 3. Connect From Your Mac

Find the VM IP from inside the VM:

```bash
ip addr
```

Look for an address like `192.168.x.x` or `10.x.x.x`.

From your Mac:

```bash
ssh <vm-user>@<vm-ip>
```

Optional SSH config on your Mac:

```sshconfig
Host watchmen-ebpf-vm
  HostName <vm-ip>
  User <vm-user>
```

Then connect with:

```bash
ssh watchmen-ebpf-vm
```

## 4. Copy or Clone Watchmen

### Option A: Clone in the VM

Inside the VM:

```bash
git clone <your-watchmen-repo-url> ~/watchmen
cd ~/watchmen
```

### Option B: Sync Your Local Working Tree

From your Mac:

```bash
rsync -av \
  --exclude node_modules \
  --exclude .next \
  --exclude .git \
  --exclude dist \
  /Users/pavel/Projects/watchmen/ \
  <vm-user>@<vm-ip>:~/watchmen/
```

Use this when you want to debug uncommitted local changes.

## 5. Generate eBPF Bindings

Inside the VM:

```bash
cd ~/watchmen/services/ebpf-agent
bpftool btf dump file /sys/kernel/btf/vmlinux format c > bpf/vmlinux.h
```

Set the target architecture.

For Apple Silicon VM:

```bash
WATCHMEN_AGENT_ARCH=arm64 go generate ./...
```

For AMD64 VM:

```bash
WATCHMEN_AGENT_ARCH=amd64 go generate ./...
```

Expected generated files:

```text
http_trace_bpfel.go
http_trace_bpfeb.go
http_trace_bpfel.o
http_trace_bpfeb.o
```

Do not hand-edit these files. They are generated by `go generate`.

## 6. Build the Agent

Inside the VM:

```bash
cd ~/watchmen/services/ebpf-agent
CGO_ENABLED=0 GOOS=linux GOARCH=$(go env GOARCH) go build \
  -buildvcs=false \
  -trimpath \
  -ldflags "-X main.version=vm-debug" \
  -o watchmen-ebpf-agent .
```

Run a compile check:

```bash
go test ./...
```

## 7. Run Locally in the VM First

Start without `WATCHMEN_ENDPOINT`. In this mode the agent prints captured events to stdout.

```bash
cd ~/watchmen/services/ebpf-agent
sudo WATCHMEN_VERBOSE=1 \
  WATCHMEN_SEND_RESPONSES=1 \
  WATCHMEN_DROP_PATH_PREFIXES= \
  WATCHMEN_DROP_COMM_PREFIXES= \
  ./watchmen-ebpf-agent
```

In another VM terminal, generate plain HTTP traffic:

```bash
curl http://neverssl.com
curl -I http://neverssl.com
curl http://example.com
```

Expected stdout from the agent:

```json
{"type":"http_request","timestamp":"...","hostname":"...","pid":1234,"uid":1000,"comm":"curl","method":"GET","path":"/","data":"GET / HTTP/1.1..."}
```

If you only generate HTTPS traffic, the agent may not see readable HTTP request lines because the payload is encrypted before it reaches the socket.

## 8. Debug From VS Code

Install these VS Code extensions on your Mac:

- Remote - SSH
- Go

Connect to the VM:

```text
Cmd+Shift+P -> Remote-SSH: Connect to Host -> watchmen-ebpf-vm
```

Open:

```text
~/watchmen
```

Build the binary before debugging:

```bash
cd ~/watchmen/services/ebpf-agent
CGO_ENABLED=0 GOOS=linux GOARCH=$(go env GOARCH) go build \
  -buildvcs=false \
  -o watchmen-ebpf-agent .
```

Add this launch config in the VM workspace at `.vscode/launch.json`:

```json
{
  "name": "Go: Debug eBPF Agent on VM",
  "type": "go",
  "request": "launch",
  "mode": "exec",
  "program": "${workspaceFolder}/services/ebpf-agent/watchmen-ebpf-agent",
  "cwd": "${workspaceFolder}/services/ebpf-agent",
  "asRoot": true,
  "env": {
    "WATCHMEN_VERBOSE": "1",
    "WATCHMEN_SEND_RESPONSES": "1",
    "WATCHMEN_DROP_PATH_PREFIXES": "",
    "WATCHMEN_DROP_COMM_PREFIXES": ""
  }
}
```

Start the debug config from VS Code.

Recommended breakpoints:

- `services/ebpf-agent/main.go`
  - `run()`: eBPF object loading and tracepoint attach.
  - `reader.Read()`: waits for ring buffer records from the kernel.
  - `decodeEvent()`: converts raw ring buffer bytes into `httpEvent`.
  - `sender.shouldDrop()`: explains why events are kept or dropped.
  - `sender.send()`: stdout mode or POST-to-Watchmen mode.
- `services/ebpf-agent/bpf/http_trace.bpf.c`
  - Read this file to understand kernel-side logic. You generally do not step through it with Delve.

## 9. Forward VM Events to Watchmen on Your Mac

First make sure Watchmen is running on your Mac:

```bash
cd /Users/pavel/Projects/watchmen
npm run dev
```

Inside the VM, find the Mac/gateway IP:

```bash
ip route | awk '/default/ {print $3}'
```

Suppose it prints:

```text
192.168.64.1
```

Test connectivity from the VM:

```bash
curl -I http://192.168.64.1:3000
```

If this fails:

- Confirm the Next server is running on the Mac.
- Confirm the VM network is shared/NAT.
- Try binding Next to all interfaces:

```bash
npm run dev -- -H 0.0.0.0
```

### Register or Reuse an Agent Credential

The `/api/agents/events` endpoint requires:

```text
X-Watchmen-Agent-Id
X-Watchmen-Agent-Secret
```

For learning, the simplest option is to run in stdout mode first. Only forward to Watchmen once local stdout capture works.

If you already have a registered local agent, reuse its ID and secret. Do not hard-code the secret in docs or commit it.

You can inspect registered agent IDs without printing secrets:

```bash
psql postgresql://pipeline:local@127.0.0.1:5432/watchmen -c "
SELECT id, provider, project_id, status, metadata, last_seen_at
FROM agent_hosts
ORDER BY last_seen_at DESC NULLS LAST;
"
```

### Run the VM Agent Against Mac Watchmen

Inside the VM:

```bash
cd ~/watchmen/services/ebpf-agent
sudo WATCHMEN_VERBOSE=1 \
  WATCHMEN_ENDPOINT=http://<mac-gateway-ip>:3000/api/agents/events \
  WATCHMEN_AGENT_ID=<agent-id> \
  WATCHMEN_AGENT_SECRET='<agent-secret>' \
  WATCHMEN_SEND_RESPONSES=0 \
  WATCHMEN_DROP_PATH_PREFIXES=/api/agents/events,/api/agents/k8s/register,/v1.,/_ping,/health,/readyz \
  WATCHMEN_DROP_COMM_PREFIXES=watchmen-ebpf,dockerd,containerd,kubelet \
  ./watchmen-ebpf-agent
```

Generate traffic in another VM terminal:

```bash
curl http://neverssl.com
curl http://example.com
```

On your Mac, confirm ingestion:

```bash
psql postgresql://pipeline:local@127.0.0.1:5432/watchmen -c "
SELECT received_at, agent_id, event_type, http_method, http_path, cluster_name
FROM agent_events
ORDER BY received_at DESC
LIMIT 20;
"
```

## 11. Code Map

```text
services/ebpf-agent/bpf/http_trace.bpf.c
  Kernel-side eBPF program.
  Hooks raw_tracepoint/sys_enter.
  Reads user-space buffers for write/send syscalls.
  Detects HTTP request/response-looking payloads.
  Writes compact events to a BPF ring buffer.

services/ebpf-agent/scripts/generate-bpf.sh
  Runs github.com/cilium/ebpf/cmd/bpf2go.
  Produces Go bindings and object files.

services/ebpf-agent/main.go
  User-space agent.
  Loads generated eBPF objects.
  Attaches the raw tracepoint.
  Reads ring buffer records.
  Decodes events into JSON.
  Filters noisy traffic.
  Prints to stdout or POSTs to Watchmen.

app/api/agents/events/route.ts
  Watchmen ingestion endpoint.
  Authenticates the agent.
  Writes durable rows into agent_events.
  Publishes live trace events.

app/api/agents/events/query/route.ts
  Query endpoint used by the UI to read durable agent events.

app/dashboard/trace/RequestTracer.tsx
  Trace UI.
  Shows live request events and animates topology.
```

## 12. Troubleshooting

### `/sys/kernel/btf/vmlinux` Missing

Use a newer Ubuntu kernel or another VM image. The current build flow depends on kernel BTF.

Check:

```bash
uname -a
ls -lh /sys/kernel/btf/vmlinux
```

### `bpf/bpf_core_read.h` Missing

Install libbpf headers:

```bash
sudo apt-get install -y libbpf-dev
```

### `go generate` Fails With Old Go Standard Library Errors

Use Go 1.22 or newer:

```bash
go version
```

Errors mentioning `cmp`, `maps`, or `slices` usually mean Go is too old.

### `go generate` Fails in `vmlinux.h` With `-Wmissing-declarations`

Some newer Ubuntu kernels generate BTF headers with forward declarations that clang reports as `-Wmissing-declarations`. The agent generator disables that warning while keeping `-Werror` for the BPF source itself:

```bash
-Wno-missing-declarations
```

If your VM copy still has the old script, update `services/ebpf-agent/scripts/generate-bpf.sh` so the `-cflags` line includes:

```bash
-Wno-missing-declarations
```

### Agent Fails to Attach

Run with sudo:

```bash
sudo ./watchmen-ebpf-agent
```

Inspect kernel capabilities:

```bash
sudo bpftool feature probe kernel
```

### Agent Runs But No Events Appear

Generate plain HTTP:

```bash
curl http://neverssl.com
```

Temporarily disable filters:

```bash
sudo WATCHMEN_VERBOSE=1 \
  WATCHMEN_SEND_RESPONSES=1 \
  WATCHMEN_DROP_PATH_PREFIXES= \
  WATCHMEN_DROP_COMM_PREFIXES= \
  ./watchmen-ebpf-agent
```

### Events Print Locally But Watchmen Receives Nothing

From the VM:

```bash
curl -I http://<mac-gateway-ip>:3000
```

Then check the agent response logs with:

```bash
sudo WATCHMEN_VERBOSE=1 WATCHMEN_ENDPOINT=http://<mac-gateway-ip>:3000/api/agents/events ./watchmen-ebpf-agent
```

Also confirm credentials are present:

```bash
echo "$WATCHMEN_AGENT_ID"
test -n "$WATCHMEN_AGENT_SECRET" && echo "secret is set"
```

### VS Code Cannot Debug as Root

Confirm the Go extension is installed on the remote VM and that the launch config includes:

```json
"asRoot": true
```

If that still fails, run the binary manually with sudo and use logs/stdout while stepping through non-root helper code with unit tests.

## 13. Clean Workflow

For normal learning:

```bash
cd ~/watchmen/services/ebpf-agent
bpftool btf dump file /sys/kernel/btf/vmlinux format c > bpf/vmlinux.h
WATCHMEN_AGENT_ARCH=$(go env GOARCH) go generate ./...
go build -buildvcs=false -o watchmen-ebpf-agent .
sudo WATCHMEN_VERBOSE=1 WATCHMEN_SEND_RESPONSES=1 WATCHMEN_DROP_PATH_PREFIXES= WATCHMEN_DROP_COMM_PREFIXES= ./watchmen-ebpf-agent
```

In another VM shell:

```bash
curl http://neverssl.com
```

In VS Code:

1. Connect with Remote SSH.
2. Open `~/watchmen`.
3. Set breakpoints in `services/ebpf-agent/main.go`.
4. Run `Go: Debug eBPF Agent on VM`.
